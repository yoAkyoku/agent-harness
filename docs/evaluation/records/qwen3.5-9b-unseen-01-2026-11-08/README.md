## 這批揭露的問題

1. **Harness 的誤殺（完成回覆檢查）**：documents-meetings 的第一次完成回覆正確寫出 `planning.md` 的決議，但因為成果中 `retro.md` 的「決議」標為未提供，`completion_summary` 要求所有提到「決議」的句子都要說明缺項而拒絕。模型改寫後回覆反而變差（刪掉正確的決議）。已在 `2026-11-08` 修正：同一標籤在成果別處有實際值時不據此拒絕。重放當天全部 31 個真實完成回覆，只有這次誤殺的判斷改變，批次 01 抓到的兩個真正問題仍被拒絕。
2. **Harness 沒有覆蓋的錯誤（錯欄引用）**：analysis-tickets 的錯誤數字引用的是確實存在的證據，只是在別的欄位。現有驗證器只檢查計算值的引用，不檢查引用 table_inspect 樣本的數字是否在標籤所指的欄位。
3. **評分工具的限制**：缺欄檢查要求同一行有檔名，以會議名稱當小節標題的正確成果會被判失敗。
4. **題目設計瑕疵**：analysis-tickets 的「各團隊的平均處理時數（hours 欄的平均）」原意是整體平均，但可理解為逐隊列出。這不影響判定（逐隊的數字在兩種解讀下都是錯的），但下一版題目應避免這種歧義。
