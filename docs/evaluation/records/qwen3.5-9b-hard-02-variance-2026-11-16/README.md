# Qwen3.5 9B hard-02：引用提示的效果與結果的變異（2026-11-16）

## 目的

[先前的 hard-02 批次](../qwen3.5-9b-hard-02-2026-11-16/README.md)留下兩個問題：

1. 幾乎每次直接回答，模型的第一個答案都沒有附引用，白白用掉一次修正。之後 harness 改成在提示裡列出實際可用的引用格式（例如 `Cite as: [orders.csv E1] [notes.md E2].`）。這個改動有沒有用？
2. 模型溫度為 0 時，重複執行的結果完全相同，「每題 3 次」量不到變異。這個題組的結果到底有多穩定？

這裡用同一個題組（[`evaluation/hard-02`](../../../../evaluation/hard-02/cases.json)，真值與評分條件沒有修改）跑了兩組：

- `t0/`：溫度 0，每題 1 次（決定性，重複沒有意義），用來和先前的批次比較。
- `t07/`：溫度 0.7，每題 3 次（`evaluation/run_suite.py --repeat 3 --temperature 0.7`），用來看變異。

所有執行都保留並計入。

## 觀察

1. **引用提示減少了浪費的修正，但不是零**。溫度 0 下，被退回的呼叫從每輪 2 次降到 0 次（少掉的是 `missing_calculation_citation` 與 `missing_answer_citation` 各一次）。溫度 0.7 下每輪仍有 1 到 2 次。
2. **同一個改動讓 `sheet-ratio` 在溫度 0 下從通過變成失敗**。提示多了一行，模型就做了不同的決定，把比率算反了。`t07` 顯示這題本來就不穩定（2/3，同樣的顛倒錯誤出現了一次），所以先前的「3/3」其實是同一個決定性結果重複三次，不是穩定通過的證據。**溫度 0 的單次結果會把不穩定的題目呈現成全對或全錯。**
3. **比率的方向是驗證器看不到的錯誤**。答案引用的是真實的計算證據，計算本身也正確，只是算的不是題目問的那個比率。和「選錯版本」一樣，這需要讀任務才能判斷。
4. **穩定通過的有五題**（3/3）：相近角色、退款比率、缺少的欄位、兩題長日誌壓縮。**穩定失敗的有一題**（`report-artifact`，0/3，原因是保守的上下文上限）。其餘三題介於中間。
5. **`delegated-vendors` 的兩次未通過都是評分條件的問題**：條件要求一定要用子代理，而且數字不能有千分位逗號。子代理失敗後模型改用自己的工具完成，其實正是設計上希望的行為。這些條件沒有修改，照樣記為未通過；下一個題組應該把「用了哪個工具」當成觀察而不是通過條件，並在比對數字前先去掉千分位。
6. **以這個題組估計，這個模型加上這個 harness 的通過率大約是七成**（19/27），但各題差異很大，27 次仍然是小樣本。
